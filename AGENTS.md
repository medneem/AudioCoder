# AGENTS.md — инструкция для AI-агентов AudioCoder

Этот файл действует для **всего репозитория**. Прочитайте его **до изменения кода**, затем изучите связанные файлы и `README.md`. Цель — дать контекст и сохранить существующие контракты, а не заменить исходники и тесты в качестве источника истины. Если инструкция расходится с фактическим кодом, перепроверьте реализацию и явно сообщите о расхождении.

## 1. Назначение и границы проекта

**AudioCoder** — портативный настольный аудиоредактор/конвертер **Windows 10/11 x64**. Основной сценарий: открыть один аудиофайл, выбрать интервал двумя маркерами на waveform, прослушать его с Fade In/Out, экспортировать в другой формат. Пользовательский интерфейс и сообщения — **на русском языке**.

- Стек: **Python 3.13**, **CustomTkinter 5.2.2**, стандартный Tkinter, Pillow, `tkinterdnd2 0.4.3`, **CTkMessagebox 2.7** и встроенный `vendor/CTkRangeSlider` (0.3).
- **FFprobe** читает метаданные, **FFmpeg** строит waveform и выполняет конвертацию, **FFplay** воспроизводит фрагменты.
- Никакого веб-сервера, БД или облачного сервиса: приложение работает локально.
- Поддерживается **один исходный файл** за раз; пакетная обработка и копирование обложек/дополнительных потоков не реализованы.
- Windows — целевая платформа; другие ОС могут позволять запуск отдельных unit-тестов, но **не являются подтверждёнными целевыми платформами GUI/Explorer/релиза**.
- Исходный аудиофайл **никогда не изменять**; предварительное прослушивание также не меняет его.

**Сначала сверяйтесь с** `README.md`, `requirements*.txt`, `.github/workflows/build-windows.yml` и тестами. Этот файл нужно обновлять, когда меняются архитектура, публичное поведение или способ сборки.

## 3. Локальный запуск и проверки

Для полноценной разработки рекомендуется **Windows + Python 3.13**. `ffmpeg.exe`, `ffprobe.exe`, `ffplay.exe` должны быть рядом с `main.py` либо в `PATH`. В упакованной версии поиск сначала проверяет папку EXE, затем `PATH` (`audiocoder/media.py`).

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-build.txt
python main.py
```

Проверки перед PR / merge:

```powershell
python -m compileall -q main.py audiocoder vendor scripts tests
python -m unittest discover -s tests -v
```

Точечный тест можно запускать как `python -m unittest discover -s tests -p "test_player.py" -v` (замените имя файла). Без Windows GUI, дисплея или бинарников FFmpeg часть тестов недоступна; **не называйте такой частичный прогон полноценной проверкой**. Интеграционные тесты могут пропускаться при отсутствии FFmpeg/FFprobe. Итоговый источник статуса Windows — **GitHub Actions**.

Существующая сборка CI:
1. Python 3.13 и `requirements-build.txt`, затем штампование версии.
2. Загрузка трёх бинарников FFmpeg из Gyan release essentials.
3. `compileall` и полный `unittest`; дополнительно поиск `Exception in Tkinter callback` / `invalid command name` в логе (Tkinter иногда только печатает исключения).
4. Создание иконки, **PyInstaller `--onefile --windowed`**, включая ресурсы CustomTkinter, TkDND, CTkMessagebox и тему.
5. Проверка состава ZIP, загрузка артефакта; после успешного push в `main` — GitHub Release.

Не редактируйте вручную `version.py` ради версии релиза: в исходниках `0.1.0-dev`, CI штампует `0.1.<github.run_number>`.

## 4. Неприкосновенные контракты аудиологики

### Интервал и позиционирование

- **Время в логике воспроизведения/экспорта хранится в секундах**, не в пикселях или нормализованных долях.
- `ClipRange(start, end, duration)` — валидный отрезок внутри файла, **минимум 0,05 с**. Проверять NaN/inf, отрицательные и выходящие за конец значения.
- Координаты в `WaveformViewport`, `WaveformView.selection` и `playhead` — **доли от полной длительности файла (0…1)**. Преобразование в секунды выполняется явно, используя `AudioInfo.duration`. Масштабирование не должно менять выбранные времена маркеров.
- Правый и левый маркеры должны оставаться упорядоченными; не вводить скрытые изменения диапазона при навигации.

### Прослушивание, повторы, навигация

- Основная кнопка прослушивает **от левого до правого маркера**; при переходе курсора внутрь фрагмента стартует с новой позиции и **не повторяет Fade In**, но сохраняет затухание у правой границы.
- Перемещение левого маркера / смена типа или длительности Fade In запускает **весь оставшийся выбранный интервал до правого маркера** с обоими эффектами.
- Перемещение правого маркера / смена типа или длительности Fade Out — **последняя секунда перед правой границей**, обрезанная левой границей, только Fade Out.
- Навигация `|◀`, `◀ −1 с`, `+1 с ▶`, `▶|` **сама запускает звук**; ей не требуется предварительный Play.
- Галочка **«Повторять фрагмент»** повторяет полное выделение и длинный предпросмотр от левого маркера **только после успешного завершения FFplay (код 0)**. Короткий предпросмотр правой границы не повторять. Не допускать циклического перезапуска при ошибке FFplay.
- Запуск нового проигрывания заменяет предыдущий; не допускать наложения FFplay. `AudioPlayer` использует lock/generation для защиты от устаревших асинхронных запусков.
- Перемещение маркера запускает предпрослушивание с debounce **250 мс** или при отпускании ползунка. Не порождать отдельный FFplay на каждый пиксель.

### Fade In / Fade Out

- Два **независимых** значения `fade_in_seconds` и `fade_out_seconds`, два алгоритма `fade_in_curve` / `fade_out_curve`, общий `fade_enabled`. `none` отключает только соответствующую сторону.
- Допустимые длительности настройки: **0,1–20 секунд**; меню предлагает 0,5 / 1 / 2 / 3 / 5 с.
- Единый источник формирования фильтров — `audiocoder/fade.py:fade_filtergraph()`. Не писать разные формулы `afade` отдельно для экспорта, плеера и waveform.
- Если сумма эффектов длиннее клипа, **пропорционально** сократить активные длительности без наложения и с сохранением их соотношения; если одна сторона `none`, другая может занять весь короткий клип.
- Для `FFplay -ss` временные метки исходного потока могут быть ненулевыми: перед `afade` **обязательно `asetpts=PTS-STARTPTS`**. Иначе фейды могут не работать/давать тишину.
- Проверять оба края при прослушивании после изменения Fade In: ранее существовал дефект, когда длинный просмотр от левого маркера подавлял Fade Out.
- `PlaybackEffects.mode` и `listening_window()` выбирают поведение `selection` / `left` / `right`; учитывать длину локального окна при построении фильтров.
- Иллюстрации waveform — лишь графика: не менять громкость исходного сигнала при отрисовке. Предпрослушивание должно использовать те же аудиофильтры, что и экспорт.

### Кодирование и файловая безопасность

- Экспорт: **FLAC / MP3 / WAV / Opus**. Доступные битрейты **128k/192k/256k/320k**, MP3 VBR — качество LAME 0–9; Opus VBR on/off. Настройки кодеков определены в `converter.py`.
- Имя результата по умолчанию: `<source_stem>_converted.<ext>`; папка — выбранная пользователем либо папка исходника.
- **Никогда не передавайте FFmpeg в качестве назначения исходный путь.** Сначала писать во временный файл `.audiocoder-*` **в папке назначения**, проверять код возврата и ненулевой размер, затем **`os.replace()`**. При отмене/ошибке прежний результат сохраняется; временный удаляется.
- Длительные FFmpeg/FFprobe задачи не запускать на Tk-потоке. Для subprocess использовать **список аргументов без `shell=True`**, не собирать команды конкатенацией путей; проверять кириллицу, пробелы, нестандартные имена.
- Успех конвертации: статус + окно `CTkMessagebox` с **двумя кнопками**. «Открыть папку» запускает `explorer.exe /select,` для готового файла, «Хорошо» (или закрытие сообщения) **не открывает Проводник**. При отмене/ошибке **не открывать папку**; ошибка Проводника не превращает успешную конвертацию в неудачную.

## 5. Tkinter, потоки, waveform и интерфейс

- **Только главный поток** изменяет Tk/CustomTkinter-виджеты и открывает диалоги. Рабочие потоки отправляют события в `self.events` (`queue.Queue`); `AudioCoderApp._poll()` извлекает их и обновляет UI. Не вызывать Tk прямо из worker callbacks.
- `_poll()` обрабатывает **не больше 120 событий за тик**; не возвращать обработку неограниченной очереди, иначе окно подвисает при частом прогрессе.
- Устаревшие результаты декодирования подавляются `source_sequence`, `_detail_generation` и `LatestOnlyWorker`. При переключении файла/закрытии — отменять таймеры, игнорировать старые события, освобождать ресурсы.
- В детализации waveform допускается один тяжёлый декодер, при активном зуме хранится только самый свежий запрос; задержка перед подробной обработкой **280 мс**. Не пересчитывать большую waveform синхронно при каждом движении мыши.
- **Не ломать утверждённый компактный макет**: главное окно без внутреннего scrollbar; waveform ≈120 px; настройки разделены на карточки; транспорт, прогресс и кнопки конвертации доступны без обрезки. Минимальная высота вычисляется по реальным `winfo_reqheight()` и DPI.
- Цвета/темы из `palette.py` и `audiocoder/themes/quiet_slate.json`, шрифты из `ui_style.py`. **Важный визуальный инвариант:** до создания любых CTk-контролов вызвать `configure_control_rendering()` из `ui_style.py`, чтобы `DrawEngine.preferred_drawing_method == "polygon_shapes"`. Стандартный на Windows `font_shapes` рисовал углы отдельными сглаженными глифами с разной видимой толщиной. Не переключать глобальный метод обратно без визуальной проверки всех кнопок, чекбоксов, карточек, меню и DPI; тест в `test_ui.py` проверяет полигональную симметрию. Поддерживать светлую, тёмную и системную темы; не вводить случайные несогласованные цвета.
- Устанавливать **собственную иконку AudioCoder в заголовке и панели задач окна**, не только в EXE: CustomTkinter 5.2.2 вызывает `iconbitmap()` с фирменным значком CTk **через 200 мс**; одного `iconphoto()` недостаточно. `AudioCoderApp._set_window_icon()` необходимо вызывать **синхронно при инициализации** и на Windows устанавливать настоящий ICO через `self.iconbitmap(str(icon_file_path()))`, до 200-мс callback CTk. `icon_file_path()` использует `sys._MEIPASS/assets/app.ico` в PyInstaller onefile и создаёт `.ico` в dev при отсутствии. В workflow обязательно оставлять `--add-data "assets/app.ico;assets"`. Канонический рисунок — `audiocoder/app_icon.py`; скрипт `scripts/build_icon.py` создаёт иконку EXE из него. Проверять это регрессионными Windows GUI-тестами.
- Диалоги создавать централизованно через `AudioCoderApp._show_message()` / **CTkMessagebox** с иконками `check`, `warning`, `cancel` и прочими поддерживаемыми; не возвращаться к стандартному `tkinter.messagebox` для новых сообщений.
- `CTkRangeSlider` использует внутренние API CustomTkinter 5.2.x; **не обновлять CustomTkinter до 6.x и не переписывать vendored widget** без отдельной проверки совместимости.
- В Windows-версии сохранять корректную работу drag & drop (один файл), путей с кириллицей и скрытых окон процессов (`CREATE_NO_WINDOW` там, где применимо).

## 6. Настройки и совместимость

- `config.json` лежит **рядом с запускаемым EXE** (в dev-режиме — в корне репозитория). Файл переносимый, в UTF-8; пользовательские значения не включать в коммиты.
- Единый источник схемы: `settings.py:DEFAULTS` + `validate()`. Сохранять через `save_settings()` (временный файл и атомарная замена); не писать JSON из разных UI-обработчиков.
- Настройки содержат последние пути, формат/битрейт/VBR, тему, fade и его две длительности, повтор, границы, zoom/offset waveform.
- При запуске программа пытается открыть **последний файл** и восстановить диапазон/вид для него. Если путь пропал, GUI должен оставаться работоспособным, без аварийного завершения.
- **Не ломать старые конфиги:** прежний общий `fade_seconds` мигрирует в `fade_in_seconds` и `fade_out_seconds`, если новые поля отсутствуют. При добавлении полей — обновить `DEFAULTS`, валидацию, при необходимости миграцию и тесты.
- Частые UI-события сохраняются **с debounce 600 мс**; не писать `config.json` на каждом событии drag/wheel.
- Ошибки настроек сообщать пользователю, а не незаметно удалять/обнулять существующий файл.

## 7. Практика изменений и тесты

1. **Определите затронутые контракты.** Найдите текущую реализацию и соседние тесты; не полагайтесь на устаревший фрагмент из истории чата.
2. **Сначала воспроизведите ошибку тестом**, если это баг; для новой логики добавьте тест до реализации. Делайте небольшие изменения по существующим слоям.
3. Покрывайте сценарии успеха, ошибки, отмены, коротких диапазонов, отдельных `none`/Fade In/Fade Out, асинхронных гонок и путей с кириллицей при изменении соответствующих функций.
4. Для изменения аудиофильтров проверяйте **команды FFplay и FFmpeg** и их одинаковую семантику; для waveform — координаты и визуальные границы; для GUI — состояние кнопок и обработку событий, не только существование виджета.
5. Тесты `tests/test_ui.py` используют один `AudioCoderApp` на класс. При новых сценариях **изолируйте состояние** (плеер, `info`, `busy`, временные файлы, очередь) и очищайте его; иначе тесты зависят от порядка.
6. В unit-тестах заменяйте внешние процессы/диалоги моками, но сохраняйте **реальные FFmpeg-интеграционные тесты**, где это обоснованно. Не запускайте настоящий Проводник или модальные окна в CI-тесте.
7. Перед слиянием проверьте `compileall`, полный `unittest`, успешный Windows CI. **Реальный звук на звуковом устройстве** и взаимодействие с настоящим Проводником невозможно подтвердить одним mock-тестом — это отдельная ручная проверка.
8. При изменении поведения обновляйте `README.md`; при изменении структуры/важных соглашений — этот `AGENTS.md` и `THIRD_PARTY_NOTICES.md` по необходимости.
9. Не смешивайте исправление с массовым рефакторингом, косметическими изменениями или обновлениями зависимостей без прямой необходимости. Соблюдайте стиль существующего Python-кода; пользовательский текст оставляйте русским.

**Где искать тесты:** `test_player.py`, `test_independent_fades.py`, `test_fade_curves.py`, `test_converter.py`, `test_integration.py`, `test_settings.py`, `test_ui.py`, `test_waveform*.py`, `test_explorer.py`, `test_drag_drop.py` и др.

## 8. Git, CI, портативный релиз

- Обычный процесс: тематическая ветка → PR → **успешный Windows CI** → merge в `main`. Проверяйте именно head SHA нужного PR, не старую сборку соседнего коммита.
- При push в `main` workflow **автоматически публикует новый GitHub Release** (даже при документационных изменениях). Не создавайте вручную новый номер, архив или тег без отдельной задачи.
- Основная ссылка для пользователей: **[Releases](https://github.com/medneem/AudioCoder/releases)**. После публикации проверяйте реальный tag и **давайте прямую ссылку на `AudioCoder-v0.1.N-windows-x64.zip` из Releases**, а не ссылку на временные Actions Artifacts.
- Портативный ZIP содержит `AudioCoder.exe`, `ffmpeg.exe`, `ffprobe.exe`, `ffplay.exe`, иконку, `VERSION.txt` и лицензии. Ресурсы темы и CTkMessagebox должны попасть **внутрь EXE**.
- Не коммитить `config.json`, `.venv/`, `tools/`, `build/`, `dist/`, `release/`, `assets/app.ico`, `assets/app.png`, `*.spec`, временные/выходные аудиофайлы.
- Учитывайте лицензии: проект MIT, сторонние компоненты и FFmpeg задокументированы в `THIRD_PARTY_NOTICES.md`. При новых зависимостях обновляйте notices и проверяйте упаковку.
